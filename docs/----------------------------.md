# منطق إدخال الأرقام والعمليات

---

## ✅ ملخص التنفيذ

### `calculatorStore.ts` — ما تم تنفيذه ومعالجته

#### `inputDigit` — تراكم الأرقام على الشاشة

```
حالة 1: waitingForOperand = true
  → يبدأ رقماً جديداً تماماً (بعد اختيار عملية)
  → يحافظ على التعبير الظاهر في السطر العلوي
  → يُعيد ضبط justCalculated ← false

حالة 2: justCalculated = true
  → يبدأ حساباً جديداً كلياً (بعد ضغط =)
  → يمسح expression القديم ومنع تراكم الأرقام على النتيجة
  → يُعيد ضبط lastOperator / lastOperand ← null

حالة 3: إدخال عادي
  → يُراكم الرقم على displayValue الحالي
  → يتجنّب الأصفار البادئة (00، 007)
  → يحترم الحد الأقصى MAX_DIGITS = 12
```

#### `selectOperator` — حفظ العملية الحسابية

```
حالة 1: waitingForOperand = true (تغيير رأي)
  → يُبدّل العملية المحفوظة بالجديدة فقط
  → لا حساب يجري

حالة 2: عملية معلّقة موجودة (سلسلة عمليات)
  → يُنهي العملية السابقة أولاً (5 + 3 × → يحسب 8 ثم يبدأ ×)
  → يُعيد ضبط lastOperand ← null لمنع تكرار = بسياق خاطئ

حالة 3: بعد justCalculated (استمرار من النتيجة)
  → يأخذ النتيجة كمعامل أول للعملية الجديدة
  → يُعيد ضبط lastOperand ← null

حالة 4: أول عملية
  → يحفظ displayValue كـ previousValue والعملية كـ operator
```

#### إصلاحات إضافية

| المشكلة | الإصلاح |
|---|---|
| `Infinity` من ضرب أو طرح أعداد كبيرة | فحص `!isFinite(result)` في `applyOperator` |
| `deleteLast` بعد `=` يحذف من النتيجة | يُعيد للصفر ويمسح كل السياق |
| `clearEntry` لا تفعل شيئاً عند `waitingForOperand` | تعود مبكراً بدون تغيير |
| `showAllClear` لم يعالج `hasError` | يُظهر AC عند الخطأ أيضاً |
| `toggleSign` عند `waitingForOperand` | لا تُطبَّق (لا يوجد رقم مُدخَل بعد) |
| دعم `Delete` key من الكيبورد | يُضاف كـ alias لـ `clearEntry` |
| دعم `F9` key | يُضاف كـ alias لـ `toggleSign` |
